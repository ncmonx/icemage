# v1.52.0 — Warm-loop detached + named pipe IPC

**Status:** draft 2026-05-27
**Branch:** `release/v1.52.0` (new, fork from release/v1.51.0 HEAD)
**Ship policy:** Win-only

## Scope

Cross-process LLM warm-pool: long-lived daemon holding loaded model + JSON-RPC over named pipe (Win) / unix socket (Linux). Eliminates ~30s cold-load per `icmg chat` / `icmg llm respond` invocation.

This delivers B3b deferred from v1.31.0 spec.

### In-scope
- `icmg llm warm --start` (detach process via Win `DETACHED_PROCESS` / unix `setsid`).
- `icmg llm warm --stop` (graceful shutdown via pipe cmd).
- `icmg llm warm --status` (ping pipe, report active model + uptime + tokens served).
- Daemon main loop: N concurrent pipe instances (default N=4), serialized at `LlamaRunner` mutex.
- Pipe protocol: JSON line-delimited, request/response with `id` field for correlation.
- Cross-platform pipe abstraction: Win `\\.\pipe\icmg-llm-warm` / Linux `~/.icmg/llm/warm.sock`.
- Client integration in `chat_cmd` + `llm_respond_cmd`: try pipe first (100ms timeout), fall back to in-process `WarmPool` on miss/error.
- PID file at `~/.icmg/llm/warm.pid` for stale-process detection on `--start`.

### Non-goals (deferred)
- Auto-start on chat invocation (explicit user gesture only).
- Idle timeout (explicit shutdown only — user-controlled lifetime).
- Multi-model hot-swap (one model loaded; restart daemon to swap).
- Encryption / auth (local-only IPC; same-user trust model).
- Streaming infer (response delivered as single JSON object after full gen).

## Architecture

```
┌────────────────────────────────────────────────────────────────┐
│ icmg chat (client)                                              │
│   inferenceCall(prompt, opts)                                  │
│     ├─ WarmClient::tryConnect(100ms)  ─────────────┐           │
│     │     hit → send JSON req → recv result → return           │
│     └─ miss/timeout → WarmPool::acquire (in-proc cold)         │
└────────────────────────────────────────────────────────────────┘
                              │ pipe IPC
                              ▼
┌────────────────────────────────────────────────────────────────┐
│ icmg llm warm-loop (detached daemon — spawned by --start)      │
│   ├─ WarmPool::acquire() lazy-load active model                │
│   ├─ PipeServer create N=4 instances                           │
│   ├─ accept loop:                                              │
│   │     ConnectNamedPipe (overlapped, multi-instance)          │
│   │     on conn → spawn worker thread → handleClient()         │
│   │     handleClient:                                          │
│   │       ReadFile JSON req                                    │
│   │       switch req.cmd:                                      │
│   │         "ping"   → write {"ok":true}                       │
│   │         "status" → write {model,uptime_s,served,active}    │
│   │         "infer"  → LlamaRunner::infer (mutex-serial)       │
│   │         "shutdown" → set stop_flag, write ack, close pipes │
│   │       WriteFile result                                     │
│   │       DisconnectNamedPipe (reuse instance)                 │
│   └─ on stop_flag → graceful close, free WarmPool, unlink PID  │
└────────────────────────────────────────────────────────────────┘
```

## Components

### NEW: `src/llm/warm_pipe.hpp`

```cpp
namespace icmg::llm {

struct PipeConfig {
    std::string name;          // "icmg-llm-warm" — used to form full path
    int max_instances = 4;
    int buffer_size = 1024 * 1024;  // 1 MB read/write buf
};

class PipeServer {
public:
    explicit PipeServer(const PipeConfig& cfg);
    ~PipeServer();
    // Accept a single connection. Blocks until client connects or stop().
    // Returns valid handle (HANDLE on Win, int fd on Linux) wrapped in
    // platform-opaque Connection. Call disconnect() to recycle instance.
    struct Connection { /* opaque */ };
    std::optional<Connection> accept(std::stop_token tok);
    void disconnect(Connection& c);
    // Stop accept loop; future accept() returns nullopt.
    void stop();
private:
    struct Impl;  std::unique_ptr<Impl> impl_;
};

class PipeClient {
public:
    // Try connect with timeout. Returns nullopt on miss.
    static std::optional<PipeClient> connect(const std::string& name,
                                              std::chrono::milliseconds timeout);
    // Send + recv newline-delimited JSON. Returns response string.
    std::string sendRequest(const std::string& json_req);
    ~PipeClient();
private:
    struct Impl;  std::unique_ptr<Impl> impl_;
};

}  // namespace icmg::llm
```

Two impls:
- `warm_pipe_win.cpp` — `CreateNamedPipeW`, `ConnectNamedPipe`, `ReadFile`/`WriteFile` with OVERLAPPED for multi-instance.
- `warm_pipe_unix.cpp` — `socket(AF_UNIX, SOCK_STREAM, 0)`, bind to `~/.icmg/llm/warm.sock`, listen+accept+epoll.

### NEW: `src/llm/warm_loop.{hpp,cpp}`

```cpp
namespace icmg::llm {

struct WarmLoopConfig {
    PipeConfig pipe;
    int worker_threads = 4;        // per-pipe-instance worker
    std::string pid_file_path;     // ~/.icmg/llm/warm.pid
};

// Main daemon entry. Blocks until pipe shutdown cmd received or signal.
// Returns 0 on graceful exit, non-zero on init failure.
int runWarmLoop(const WarmLoopConfig& cfg);

}
```

Loop body:
1. Write own PID to `pid_file_path`.
2. Set llama log to silent callback (already exists).
3. `WarmPool::instance().acquire()` — lazy-load model. On fail → log + exit 1.
4. Create `PipeServer` with N=4 instances.
5. For each pipe instance: spawn worker thread accepting + handling clients.
6. Main thread: wait on stop_token (set by `shutdown` cmd handler).
7. Worker threads observe stop → exit.
8. Join all workers; close pipes; release WarmPool; unlink PID.

### NEW: `src/cli/commands/llm_warm_cmd.cpp`

Subcommand under existing `llm` parent: `icmg llm warm <action>`.

Actions:
- `--start` — fork+detach (Win `CreateProcessW` with `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`; Linux `fork()+setsid()+fork()`). Child calls `runWarmLoop()`. Parent prints PID + exits 0. Pre-check: if PID file exists + process alive + pipe responds to ping → already running, print info, exit 0. Stale PID (file exists, process dead) → unlink + proceed.
- `--stop` — connect pipe, send `{"cmd":"shutdown"}`. On success print "stopped (pid N)". On miss (no pipe) print "not running".
- `--status` — connect pipe, send `{"cmd":"status"}`, pretty-print result (model id, uptime, tokens served, active connections). Miss → "warm-loop not running. Start with: icmg llm warm --start".

## Pipe Protocol

Newline-delimited JSON.

**Request** (single line, `\n` terminated):
```json
{"id":"<uuid-v4>","cmd":"infer","prompt":"<text>","max_tokens":512,"temperature":0.7,"top_p":0.9,"stop":["<|im_end|>"]}
```

Other `cmd`:
- `"ping"` — minimal request, returns `{"id":...,"ok":true}`. Used for `warmAvailable()` probe.
- `"status"` — returns `{"id":...,"ok":true,"model":"<id>","uptime_s":N,"served":M,"active_clients":K,"loaded_at_iso":"..."}`.
- `"shutdown"` — daemon acks then exits. Returns `{"id":...,"ok":true,"shutting_down":true}`.

**Response** (single line, `\n` terminated):
```json
{"id":"<uuid>","ok":true,"text":"<reply>","tok_in":N,"tok_out":M,"wall_ms":N,"finish_reason":"<stop|length|error>"}
```

**Error response:**
```json
{"id":"<uuid>","ok":false,"err":"<msg>","err_code":"<no_model|busy|timeout|infer_fail>"}
```

Max message size = 1 MB (`PipeConfig::buffer_size`). Larger prompts → split client-side or reject server-side.

## Error handling

| Scenario | Behavior |
|---|---|
| Daemon process crashes mid-infer | Client read times out (60s) → DisconnectNamedPipe → fall back to in-process WarmPool. Stale PID file removed by next `--start`. |
| Pipe creation fails (already exists from prior crash) | `--start` checks PID file; if process dead → unlink + retry. If alive + pipe responds → print "already running" + exit 0. |
| Model load fails in daemon | Write error to stderr (in case daemon launched interactively for debug), unlink PID, exit 1. Client `tryWarmInfer` returns nullopt → in-process fallback. |
| Client connect timeout (100 ms) | Return nullopt immediately, fall back. No retry. |
| Concurrent infer requests | LlamaRunner mutex serializes. p99 latency for Nth queued client = N × per-request time. Documented limitation. |
| Daemon receives `shutdown` cmd while client mid-infer | Worker finishes current infer + writes response. Stop flag observed at next `accept()`. Graceful drain ~1-2 sec. |
| User Ctrl-C in foreground daemon (debug mode) | SIGINT handler sets stop_token; same path as `--stop` cmd. |
| pipe.sendRequest fails mid-stream (EPIPE) | Caller logs + returns nullopt. Fallback. |
| Active model changes (`icmg llm use X`) while daemon running | Daemon NOT reloaded. Client requests still use old model. Documented limitation: restart daemon (`--stop` + `--start`) to pick new active. |

## Migration notes

- Existing `WarmPool::acquire` API unchanged; `tryWarmInfer` is layered on top.
- No DB schema changes.
- New env var `ICMG_NO_WARM_LOOP=1` skips client probe entirely (always in-process fallback).
- Settings: PID file path + pipe name configurable via `~/.icmg/config.json` keys `llm.warm.pid_path` + `llm.warm.pipe_name` (optional; defaults used if absent).

## Failure modes (adversarial)

1. **CRITICAL → mitigated:** Daemon orphaned consuming 5GB RAM if user forgets `--stop`. **Mitigation:** explicit OPT-IN start (user already mentally committed to extra RAM); `--status` shows uptime as reminder; docs explicitly call out manual lifecycle.

2. **CRITICAL → mitigated:** Pipe race on concurrent `--start` calls. **Mitigation:** PID-file-based mutex: `--start` checks PID file with O_EXCL semantics (Win equivalent: `CreateFileW` with `CREATE_NEW`); second concurrent start sees file exists + process alive + pipe responds → exits 0 "already running".

3. **CRITICAL → mitigated:** Daemon crash mid-infer hangs client. **Mitigation:** 60s read timeout + EPIPE detection → fallback path; client returns to in-process flow transparently.

4. **MINOR (documented non-goal):** Switching active model (`icmg llm use X`) doesn't reload daemon. User must `--stop` + `--start`. Documented; future v1.53 could add `reload` cmd.

5. **MINOR (documented non-goal):** Pipe corruption on partial write (e.g. abrupt power-off). Next read sees garbage → parse fail → error response. Acceptable; user re-issues request.

6. **MINOR (documented non-goal):** Pipe permission inheritance — same-user trust only. Different-user clients fail to connect (Win named pipes default to creator's user). Acceptable for local dev tool.
