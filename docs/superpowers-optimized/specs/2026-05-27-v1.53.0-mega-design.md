# v1.53.0 mega — warm polish + smart router + dedup/parallel + NL ambiguity

**Status:** draft 2026-05-27
**Branch:** `release/v1.53.0` (forked from `release/v1.52.0` HEAD `163ed34101`)
**Ship policy:** Win-only mega bundle, single release at end of all 4 sub-features.

## Sub-features

### A. Warm-loop polish (~2h, priority 1)
- **A1**: Fix `active_clients` counter leak — increment on accept but decrement missing on disconnect path under some conditions. Audit `warm_loop.cpp` worker loop.
- **A2**: When warm pipe ping succeeds, in-process `WarmPool::acquire` should auto-skip (daemon owns model → RAM-guard would spuriously refuse). Set `ICMG_LLM_DAEMON_OWNS_MODEL` flag in `tryWarmInfer` probe path that suppresses local acquire fallback when daemon visible.

### B. Smart router (~3h)
- **B1**: `src/cli/router.{hpp,cpp}` new module. `classifyPrompt(text) → enum {LOCAL, CLOUD, CACHE}`.
- **B2**: Heuristics — short (<80 chars) + simple keywords (define/what is/list/format/translate) → LOCAL. Tool-heavy verbs (debug/refactor/build/deploy) → CLOUD. Repeated prompt (hash hit) → CACHE.
- **B3**: Wire into hook (`UserPromptSubmit`) — emit routing hint as additionalContext.
- **B4**: Tests: 6 unit (classifier rules) + 1 integration.

### C. C1 prompt deduper + C3 hook parallel (~4h)
- **C1**: Hash + dedup of identical PreToolUse:Bash prompts within 60s window. Cache in `~/.icmg/dedup.db`. Hit → reuse prior result. Subsystem: `src/cli/dedup_cache.{hpp,cpp}`.
- **C3**: Hook chain runner — when multiple hooks registered for same event, run in parallel via `std::thread::async` instead of sequential. New: `src/core/hook_parallel.cpp`.
- **C4 already done** v1.51 (rule auto-correct via NL detect).

### D. NL ambiguity disambiguation (~2h)
- **D1**: Extend `src/cli/auto_rule.hpp::handleNL` ambiguous path. Currently lists candidates + does nothing. Add: stash candidates + return "(ambiguous — pick 1/2/3 next turn)" + on next plain user message, parse as numeric pick → execute disambiguated action.
- **D2**: REPL state holds `pending_disambig: optional<vector<FuzzyMatch> + NLAction>`. Cleared on numeric input or any other action.
- **D3**: 3 unit tests for stash/pick/clear paths.

## Non-goals
- Linux warm-loop impl
- Cloud router LLM-based classifier (regex only)
- Dedup across processes (single-machine same-user only)
- Hook parallel for `Stop`/`UserPromptSubmit` (those need sequential for chain rules; only `PreToolUse` + `PostToolUse` parallelize)

## Architecture deltas

### A1 fix
`warm_loop.cpp` worker thread:
```cpp
while (!stop) {
    auto conn = server.accept(tok);
    if (!conn) break;
    ds.active_clients++;        // ← increment
    try {
        auto req = server.readMessage(**conn);
        auto resp = handleRequest(req, ds, *runner, model_id);
        server.writeMessage(**conn, resp);
    } catch (...) {}            // ← ensure decrement even on throw
    server.disconnect(**conn);
    ds.active_clients--;        // ← decrement (currently missing in some paths)
}
```
RAII guard `struct ClientCounter { ~ClientCounter(){--ds.active_clients;} };` instead of manual ++/--.

### A2 daemon-aware acquire
In `chat_cmd.cpp` after `tryWarmInfer` returns nullopt: if `warmAvailable()` was true at start (daemon present but request failed), skip `WarmPool::acquire` path entirely; print explicit error + fall through to agent. Avoids the "warm-pool acquire: load failed: RAM guard refuse" noise.

### B router
```cpp
namespace icmg::cli {
enum class Route { LOCAL, CLOUD, CACHE };
struct RouteDecision { Route route; double confidence; std::string reason; };
RouteDecision classifyPrompt(const std::string& text);
}
```
Rule precedence:
1. Hash → cache lookup → CACHE if hit (<60s old).
2. Length <80 + question keywords (apa/what/how/define/list/format) → LOCAL high-confidence.
3. Tool verbs (build/test/deploy/refactor/grep/edit) → CLOUD.
4. Default → CLOUD low-confidence.

### C1 dedup
SQLite table `prompt_dedup(hash TEXT PRIMARY KEY, prompt TEXT, result TEXT, ts INTEGER)`. Hash = FNV-128 of prompt. On PreToolUse:Bash hook fire, check hash; if hit within `dedup_window_sec=60`, return cached result + emit hook decision=block with reason "deduped".

### C3 hook parallel
`runHookChain(event, hooks)` currently calls each hook sequentially. Change to:
- Identify independent hooks (no shared mutable state declared in hook config — assume independent by default; opt-out via `"sequential": true` in hooks.json).
- Spawn N threads via `std::async`, join all, aggregate decisions.
- Block decision if ANY hook blocks (worst-case wins).

### D ambiguity
`NLAction::PICK_PENDING` new enum value. `handleNL` when ambiguous → returns ack `(ambiguous: 1=foo 2=bar 3=baz — pick 1/2/3)` + sets adapter callback `setPendingDisambig(candidates, original_action)`. Next REPL turn: if user input is "1"/"2"/"3" and pending exists → resolve to that candidate id + execute original action with resolved target. Else clear pending.

## Failure modes (adversarial)

1. **CRITICAL → mitigated:** C3 hook parallel introduces race in shared state. **Mitigation:** opt-in via `"parallel": true` in hooks.json; default sequential. Documented constraint.
2. **CRITICAL → mitigated:** B router misclassifies — short Indonesian question may not match English keywords → CLOUD bias. **Mitigation:** ID keyword list (apa/jelaskan/bagaimana/tolong/format). Plus add `--route=local` CLI override.
3. **MINOR (documented non-goal):** Dedup may return stale result if external state changed within 60s window. Acceptable for read-only commands; user can `ICMG_NO_DEDUP=1` to opt out.
4. **MINOR (documented non-goal):** A1 counter still racy if accept() returns nullopt mid-thread; RAII guard fixes most cases but `accept()` itself may bump counter prematurely — review carefully.
