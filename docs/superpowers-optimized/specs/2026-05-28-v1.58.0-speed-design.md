# v1.58.0 mega — Speed bundle (Tier 1) + v1.57 followups

**Status:** draft 2026-05-28
**Branch:** `release/v1.58.0` (forked from v1.57.1 HEAD)
**Ship policy:** Win-only mega, multi-session exec.
**Theme:** compound hot-path latency cut on reads + writes.

## Scope (4 speed + 2 followups)

### F2 — Memory-mapped DB hot-read (~3h)
SQLite `PRAGMA mmap_size=N` on project + global DBs so hot tables
(memory_nodes, graph_nodes) read zero-syscall via the OS page cache.
**Mechanism:** set mmap_size at Db open (after WAL pragma). Size tuned to
DB file size, capped (e.g. 256 MB) to avoid address-space waste on 32-bit.
**Win:** 2-3× on recall + context.
**Files:** `src/core/db.cpp` (Db ctor pragma).

### F3 — Bloom filter negative lookups (~2h)
In-RAM bloom over graph node paths so "node not in graph?" is O(1) and
avoids a SQL round-trip on the common miss. False-positive < 0.1% (k=7,
m sized to node count). Rebuilt on graph load; updated on insert.
**Win:** cold negative queries 10×.
**Files:** `src/graph/node_bloom.{hpp,cpp}`, hook into `GraphStore::getNode`
fast-path.

### F4 — Async batch writes (~2h)
Queue graph/memory writes; background thread flushes every 100 ms (or on
queue depth threshold / explicit flush / process exit). `icmg graph update`
returns without blocking on each INSERT.
**Win:** graph update 3-5×.
**Files:** `src/core/write_queue.{hpp,cpp}`, opt-in via GraphStore.
**RISK:** durability — a crash before flush loses queued writes. Mitigation:
flush on normal exit (atexit/RAII) + cap queue age at 100 ms; writes are
regenerable (graph is derived from source), so loss is non-fatal.

### F5 — Predictive prefetch (~4h)
Telemetry: record command bigrams (cmd N → cmd N+1) in a small table.
On each command, look up the most-likely next command and pre-warm its
context bundle in a background thread. Opt-in `ICMG_PREFETCH=1`.
**Win:** 30-50% wall-clock on predictable sequences (context→symbol→recall).
**Files:** `src/core/cmd_bigram.{hpp,cpp}`, dispatcher tap.

### FU1 — persona_db unit test (followup)
TDD gap from v1.57 S2. tests/core/test_persona_db.cpp covering
read/write/available + legacy fallback + ACL no-throw.

### FU2 — daemon glossary cross-call (followup)
icmg-server holds one SessionGlossary per session_id; dispatch threads
the request session_id through Stage 5 so tokens persist across calls
within a daemon session (currently process-glossary only, lost per call).
**Files:** `src/server/icmg_server.cpp` (session_id → glossary map).

## Failure modes (adversarial)

1. **F2 mmap_size too large on big DB** → address-space exhaustion (32-bit
   builds, or huge multi-GB DBs). Mitigation: cap at 256 MB; never exceed
   2× file size.
2. **F3 bloom stale after external DB edit** → false "not present", missing
   a node that exists. Mitigation: bloom is a NEGATIVE fast-path only — a
   bloom "maybe present" still does the SQL; only "definitely absent"
   short-circuits, and absent is verified by rebuild-on-load. Conservative:
   on any insert, add to bloom; on miss, fall through to SQL (never trust a
   bloom "absent" if the bloom wasn't built this process).
3. **F4 async write loss on crash** → queued graph writes vanish. Mitigation:
   graph is regenerable from source (icmg graph update re-derives); flush on
   exit; this is acceptable for derived data, NOT for memory/decisions
   (those stay synchronous — async ONLY for graph_nodes/edges).
4. **F5 prefetch wastes cycles on wrong prediction** → background work for a
   command that never comes. Mitigation: opt-in env; cap prefetch to 1
   in-flight; cancel on actual next-cmd mismatch.
