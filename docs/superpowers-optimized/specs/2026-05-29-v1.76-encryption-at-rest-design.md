# v1.76 — Encryption-at-Rest Design

**Status:** Approved 2026-05-29
**Goal:** Encrypt icmg's SQLite databases at rest so memory, decisions, and transcripts are not readable as plaintext on disk.
**Ship as:** v1.76 (own release).

## Scope

In:
- Transparent **full-DB encryption** of the project DB (`.icmg/<project>.db`) and global DB (`~/.icmg/global.db`).
- **FTS5/BM25 recall keeps working** (full-DB encryption decrypts pages transparently — index lives inside the encrypted DB).
- **Opt-in**, with selectable scope: both DBs (default) or project DB only.
- **3 key-modes**: `dpapi` (default, single-user), `shared` (shared-server multi-user, 1 DB file), `env` (CI/server via `ICMG_DB_KEY`).
- **Auto-migration** of existing plaintext DBs on enable, with `.bak` backup + atomic swap + rollback.
- New command `icmg encrypt {enable|disable|status}`.

Non-goals (documented limitations):
- **Field-level / column crypto** — rejected: encrypting TEXT columns kills BM25 indexing (icmg's core recall).
- **Passphrase-per-invocation** — rejected: icmg is hook-driven (called hundreds of times/session); a per-call prompt is unusable.
- **In-memory protection** — data is plaintext in RAM while a command runs; out of scope.
- **Cloud key escrow / recovery** — local-first; if the key is lost, data is unrecoverable (mitigated by opt-in + backup + loud docs).
- **mmap on encrypted DBs** — v1.58 F2 mmap may be auto-disabled when a DB is encrypted (SQLCipher page cipher); acceptable, documented.

## The "1 project, 2 users" question (resolved)

icmg's normal team model: each user has their **own local DB**; shared knowledge moves via **`icmg sync` (git-tracked JSONL)**, NOT by sharing the raw `.db` file. Under this model `dpapi` (key sealed to one Windows account) is correct — each user encrypts their own local DB, sync still works.

For **shared-server deployments** that genuinely share one `.db` file across Windows users (cf. v1.56 `relaxAclEveryone` on `.icmg/data.db`), DPAPI would lock user B out of user A's DB. Resolved by key-mode:

| key-mode | for whom | key storage |
|---|---|---|
| `dpapi` (default) | single-user (majority) | `~/.icmg/db.key` wrapped via DPAPI `CryptProtectData` (sealed to the Windows account) — zero prompt |
| `shared` | shared-server, 2+ users, 1 DB file | key file with team-readable ACL (reuse `relaxAclEveryone`) |
| `env` | CI / server | `ICMG_DB_KEY` (hex) |

Recommendation surfaced in docs: shared teams should prefer **separate local DBs + `icmg sync`** over a shared `.db` file.

## Architecture

### Crypto: SQLCipher + OpenSSL
- **PIVOT (2026-05-29, Task 1 gate):** SQLCipher 3.53.1 has **no CNG provider** (only CC/OpenSSL/LibTomCrypt/Custom). Original CNG/zero-DLL premise is INVALID. Per gate decision → **OpenSSL provider** (`SQLCIPHER_CRYPTO_OPENSSL`).
- Replace the vendored `third_party/sqlite3/sqlite3.c` with the **SQLCipher amalgamation** (`third_party/sqlcipher/`, generated via `make sqlite3.c` from sqlcipher 3.53.1), compiled with `SQLITE_HAS_CODEC` + `SQLITE_EXTRA_INIT=sqlcipher_extra_init` + `SQLITE_EXTRA_SHUTDOWN=sqlcipher_extra_shutdown` + `SQLCIPHER_CRYPTO_OPENSSL`.
- Windows: link MSVC OpenSSL `libcrypto` (via vcpkg `openssl:x64-windows`). POSIX: system `crypto`.
- **Bundle grows 12 → 13 files**: adds `libcrypto-3-x64.dll`. Single-binary-ish preserved (sidecar DLL like the others).

### Single choke point: `Db::Db(path)`
All 10 DB-open sites route through `Db::Db(const std::string& path)` (`src/core/db.cpp:23`). After `sqlite3_open_v2`, **before** `applyPragmas()`:
- If encryption is active for this DB scope, run `PRAGMA key="x'<hexkey>'"` (raw 256-bit key as hex — skips SQLCipher's KDF since we supply a full random key).
- Then existing pragmas (WAL, etc.) run as today.
- Encryption-active is resolved once per process from config + key-mode.

### New module: `src/core/db_key.{hpp,cpp}`
- `EncryptionConfig resolveEncryptionConfig()` — reads `~/.icmg/encrypt.json` (enabled, scope, key_mode) + env overrides.
- `std::string resolveDbKey(const EncryptionConfig&)` — returns hex key:
  - `env` → `ICMG_DB_KEY` (validated hex, 64 chars).
  - `dpapi` → unwrap `~/.icmg/db.key` via `CryptUnprotectData`.
  - `shared` → read `~/.icmg/db.key` (raw hex, ACL relaxed).
- `std::string generateDbKey()` — 32 bytes `BCryptGenRandom` → hex (reuse `server_token` CSPRNG pattern).
- DPAPI wrap/unwrap helpers (`CryptProtectData`/`CryptUnprotectData`), POSIX fallback = 0600 file.
- **Pure-testable seams:** hex encode/decode, key-mode priority resolution, config parse — unit-tested without touching DPAPI.

### New command: `src/cli/commands/encrypt_cmd.cpp`
- `icmg encrypt enable [--scope both|project] [--key-mode dpapi|shared|env]` — generate/seal key, write `encrypt.json`, migrate existing DBs.
- `icmg encrypt disable` — decrypt DBs back to plaintext (export to plaintext, swap, backup), clear config. (Provides the escape hatch / un-lock path.)
- `icmg encrypt status` — show enabled, scope, key-mode, per-DB encrypted/plaintext state.

## Migration (auto + backup)
On `icmg encrypt enable`, for each in-scope DB:
1. If already encrypted → skip.
2. Copy `<db>` → `<db>.pre-encrypt.bak`.
3. Open plaintext, `ATTACH DATABASE '<db>.enc' AS enc KEY "x'<hexkey>'"`, `SELECT sqlcipher_export('enc')`, `DETACH enc`.
4. Atomic swap `<db>.enc` → `<db>` (rename-aside on Windows lock, same pattern as `update_cmd`).
5. On any failure → restore from `.bak`, abort, report.
`disable` runs the inverse (`sqlcipher_export` to a plaintext ATTACH).

## Error handling
- Wrong/missing key (open then first query → SQLCipher "file is not a database") → map to: `DB is encrypted and the key doesn't match or is missing. Run 'icmg encrypt status'.` (no crash).
- DPAPI unwrap fails (different user / moved profile) → message + suggest `--key-mode shared` or restore key file.
- `enable` when already enabled → no-op + status.
- Migration partial failure → `.bak` restore, non-zero exit, clear message.

## Testing strategy (TDD — failing test first per task)
- `test_db_key`: hex roundtrip; key-mode priority (env > explicit > dpapi default); config parse; `generateDbKey` length/hexness; DPAPI wrap→unwrap roundtrip (Windows).
- `test_encrypt_migration`: plaintext→encrypted roundtrip preserves all rows; **BM25 recall still finds a seeded memory** after encryption; `disable` returns to readable plaintext.
- `test_encrypt_wrongkey`: opening encrypted DB with wrong key → clean mapped error, not crash/abort.
- `test_encrypt_backcompat`: encryption OFF → plaintext DB opens and works exactly as today (no regression).
- Build-spike gate (Task 1): confirm SQLCipher+CNG compiles + runs on MSVC before any wiring; if it fails, pivot to OpenSSL provider before proceeding.

## Rollout / migration notes

## Risks (failure-mode check)
- **CRITICAL — key loss = permanent lockout.** Mitigation: opt-in + `.bak` on migrate + `disable` escape hatch + loud docs. Inherent to encryption; documented.
- **CRITICAL — SQLCipher+CNG MSVC build.** Mitigation: Task 1 is a build spike; pivot to OpenSSL provider before further work if it fails.
- **Handled — DPAPI + shared DB:** 3 key-modes.
- **MINOR — WAL/mmap interplay:** auto-disable mmap on encrypted DBs; documented non-goal.
