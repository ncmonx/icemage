# v1.58.0 Implementation Plan — Speed bundle + followups

> **For Claude:** REQUIRED SUB-SKILL: `executing-plans` (sequential, multi-session, TDD-gated).

**Goal:** Compound hot-path latency cut — mmap reads, bloom negative lookups, async graph writes, predictive prefetch — plus two v1.57 followups.
**Architecture:** All changes localized to `src/core/` (db, write_queue, cmd_bigram), `src/graph/` (node_bloom), `src/server/` (glossary cross-call). No public CLI surface change except opt-in env flags.
**Tech Stack:** C++17, SQLite pragmas, std::thread, std::filesystem.
**Assumptions:**
- mmap_size is honored by the bundled SQLite (3.x). Will NOT help if SQLite compiled without SQLITE_MAX_MMAP_SIZE.
- Async writes apply ONLY to derived graph data (regenerable). Memory/decisions stay synchronous — durability required there.
