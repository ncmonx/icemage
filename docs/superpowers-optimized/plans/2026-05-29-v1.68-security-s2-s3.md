# v1.68.0 Security Bundle — S2 daemon IPC token auth + S3 secret-scanner FS mode

> **For Claude:** Execute via TDD (failing test first). Source → private remote only.

**Goal:** Authenticate icmg-server IPC clients with a per-user token, and add a filesystem secret-scanning command.
**Architecture:** S2 adds a `token` field to the RPC wire protocol + a server-side auth gate before dispatch; token lives in `~/.icmg/server.token` (0600 POSIX). S3 adds a core FS-walk wrapper around the existing `scanSecrets()` plus a new `icmg scan` command.
**Tech Stack:** C++17, nlohmann/json, SQLite (unchanged), MSVC release build.
**Assumptions:**
- Named-pipe daemon is single-user (token file in user home is the trust boundary). Will NOT defend against same-user processes — only cross-user pipe clients.
- S3 reuses the 21 existing patterns in `secret_scanner.cpp`; NOT adding new detectors this release.

## S2 — Daemon IPC token auth

Current gap: `IcmgServer` accept loop dispatches any well-formed request from any pipe client (incl. `shutdown`). No auth.

### Task S2.1: server-token core helper (TDD)
**Files:**
- Create: `src/core/server_token.hpp`, `src/core/server_token.cpp`
- Test: `tests/core/test_server_auth.cpp`

API:
```cpp
namespace icmg::core {
std::string serverTokenPath();                 // globalDir()/server.token
std::string loadOrCreateServerToken();         // gen 32-hex if missing, write 0600, return
std::string readServerToken();                 // existing token or "" if none
bool tokenMatches(const std::string& expected, // constant-time-ish compare;
                  const std::string& got);      // expected=="" => false (fail closed)
}
```
- Generate: 16 random bytes (`std::random_device`) → 32 lowercase hex.
- POSIX: `chmod(path, 0600)`. Windows: rely on user-profile dir ACL (no-op chmod).
- `tokenMatches`: length check + full-scan equality (no early return on first mismatch).

**Step 1:** test_server_auth: loadOrCreate creates non-empty 32-char hex; second call returns same; tokenMatches(t,t)=true; tokenMatches(t,"x")=false; tokenMatches("","")=false; tokenMatches("",t)=false.
**Step 2:** implement.

## v1.69.0 ADDENDUM — icmg-first auto-enforce + UTF-8 abort fix (bundled)

**Field bug (fix):** `icmg hook userprompt` builds an augmented prompt from memory content and `json::dump()`s it; invalid UTF-8 (raw bytes in a memory row) throws `type_error.316` → uncaught → abort, killing the prompt hook. Fix: `core::safeDump` (`error_handler_t::replace`) applied to hook_cmd (6), daemon_cmd, rpc_protocol, serve_cmd. test_json_safe (3). Same class as v1.61 sync_cmd.

**Feature (user request):** new project / new user on an existing project should NOT need manual memory seeding to make the icmg-first rule stick.
- Decision: **always-on hook** (chosen over recall-seed): `icmg init` writes `.claude/hooks/icmg-icmg-first.sh`, registered in `settings.local.json` UserPromptSubmit alongside persona/advisor.
- Behavior: full rule first turn, one-line reminder thereafter (dedup marker `~/.icmg/icmg-first-injected/<session_id>`); opt-out `ICMG_NO_ICMG_FIRST=1`. Deterministic (not BM25-dependent).
- Result: any project/user that runs `icmg init` gets the rule enforced every prompt — zero manual `icmg store`.
