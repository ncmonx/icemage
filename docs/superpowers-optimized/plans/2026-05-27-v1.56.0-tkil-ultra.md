# v1.56.0 Implementation Plan — Tkil Ultra + extras

> **For Claude:** REQUIRED SUB-SKILL: `executing-plans` (sequential, multi-session).

**Goal:** Cut command-output tokens to absolute minimum via 5-stage Tkil pipeline + long-lived daemon + strict enforce.
**Architecture:** Existing `tkil::BaseFilter` becomes Stage 1 of a 5-stage chain. Stages 2–5 add dedup, pattern collapse, outcome-only, and session glossary. A new RPC daemon (`icmg-server`) holds session state cross-call. Strict-enforce hook hard-blocks native tools with icmg equivalents.
**Tech Stack:** C++17, named-pipe IPC (Win), JSON-line protocol, regex profiles.
**Assumptions:**
- Tkil filter pipeline order is order-independent for filters that read text (each pass treats input as plain UTF-8 text). **Will NOT work if** any future pass needs structured input (e.g., AST).
- Win named-pipe IPC for daemon. **Will NOT work on Linux** until ported (out of scope v1.56).
- Session = single Claude Code session, identified by `session_id` hook field.

**Step 2: Implement**
Public API:
```cpp
namespace icmg::tkil {
struct DedupOpts { int max_lookback = 1; double prefix_ratio = 0.8; int max_levenshtein = 3; };
std::string dedupPass(const std::string& in, const DedupOpts& opts = {});
}
```
Algorithm: streaming over lines; for each line, compare to previous N lines (lookback). If match (identical OR Levenshtein ≤ 3 OR shared prefix ≥ 80%), increment counter; emit `<line> (×N)` on next-distinct flush.

Always-verbatim allowlist regex: `\b(error|fail|FATAL|FAILED|LNK\d{4}|RC\d{4}|C\d{4}):`. Match → never collapse.

**Step 3: Verify task**

### Task 6: T1 wire pipeline + `--ultra` flag

**Files:**
- Modify: `src/tkil/filter.cpp`, `src/cli/commands/run_cmd.cpp`

**Step 1: Add `--ultra` CLI flag + `ICMG_TKIL_ULTRA=1` env detection.**

**Step 2: Wire 5-stage pipeline** in `filter.cpp`:
```cpp
std::string applyPipeline(const std::string& raw, const Context& ctx) {
    auto s = stage1_baseFilter(raw, ctx);
    if (!ctx.ultra) return s;
    s = stage2_dedup(s);
    s = stage3_patternCollapse(s, ctx.detector);
    if (ctx.outcome_only_eligible) s = stage4_outcomeOnly(s, ctx);
    s = stage5_sessionGlossary(s, ctx.session_id);
    return s;
}
```

**Step 3: Auto-trigger heuristic** — if output > 5KB AND dup-ratio > 0.4, enable ultra automatically. Dup-ratio = (lines - distinct_lines) / lines.

**Step 4: Verify** — `icmg --ultra run npm install` on test fixture → output < 200 bytes.

**Step 1: RPC protocol.** JSON-line over `\\.\pipe\icmg-server`:
```

< {"ok":true,"out":"<filtered output>","took_ms":12}
> {"cmd":"shutdown"}
< {"ok":true}
```

**Step 2: Daemon loop** — `icmg server --start` spawns detached process. Loop: accept pipe connection → dispatch via `Registry<BaseCommand>` → return JSON. Reuse warm-loop pipe pattern from v1.52.

**Step 3: Client auto-connect** — `dispatcher.cpp`: before in-process dispatch, try connect to pipe. On success, forward args + read response. On failure, fall through to current code path.

**Step 4: Glossary cross-call** — daemon holds session_glossary map keyed by session_id; client passes session_id; T1 Stage 5 reads from daemon-side map instead of disk.

**Step 5: Tests** — `tests/server/test_rpc_protocol.cpp`, `tests/server/test_daemon_lifecycle.cpp`.
